# Report what was observed, derived, assumed and unknown

Attach to every claim the observation that establishes it. Keep the things that were never looked at separate from the things that were seen to be absent.

## When to use it

Use it in every report, summary, review and handover, and above all when a statement begins with no, none, never or all.

## Steps

1. Separate explicit facts, derived values, assumptions and unknowns.
2. Attach to each claim the observation behind it. Mark every claim that rests on no observation.
3. Distinguish what was observed to be absent from what was never looked at. Never report the second as the first.
4. Keep unknown, conflicting, insufficient and blocked as states. Do not turn them into yes or no.
5. Label synthetic, estimated and analogous material wherever it appears in the result.
6. Make a reported failure name three things: what was attempted, what was observed, and which of the two disagreed with the contract.
7. Name what is relied on without ever having been stated, and mark each item as observed, derived or merely assumed.

## Checks

- Every sentence that uses no, none, never or all names the scope that was actually searched.
- Every number is marked as measured or estimated.
- Every failure states its own cause.
- A reader can repeat each observation from what is written.

## Known-wrong example

A report says that there are no other usages of a function. The search covered one source folder. The test folder and the scripts folder were never opened. The honest sentence is: no usage was found in the source folder, and the test folder and the scripts folder were not searched. The first sentence leads to a deleted function and a broken script.

## What to record

- Each claim with its kind and its observation.
- The scope of every search: what was covered and what was not.
- Each failure with the attempt, the observation and the disagreement.
