# How Loop Engine works

```text
Operational runtime type
└── Loop
    ├── Relationship: Starting, Spawned by, Queried by, Retrieved by, Connected from
    ├── Role: Practitioner, Intelligence, Solution
    ├── Mode: deterministic, hybrid, non-deterministic
    ├── Exact definition, contract, profile, and typed ports
    ├── Budget, permissions, effects, and deadline
    └── Run History
```

The Practitioner determines what work the task requires. Intelligence Loops
find, select, and materialize information. Solution Loops perform finished
transformations and authorized effects.

`LoopGraphDefinition` is the reusable graph authority. Dynamic work is recorded
through exact Loop relationships in Run History.

Reactive series may receive events or schedules, but each activation is finite.
Candidates remain immutable, independent evaluators attach evidence, and
portfolio policies create current ranked views without waking producers.

The model proposes semantic decisions. Deterministic supervisors retain
permissions, tool execution, evidence gates, liveness, and terminal authority.
