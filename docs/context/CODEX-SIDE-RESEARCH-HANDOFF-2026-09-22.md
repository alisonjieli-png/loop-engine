## Search evidence to preserve

The [candidate-only search](../../artifacts/first-party-harness-candidates-2026-09-22/search_candidates.py)
checks exact file digests and returns metadata cards, never native bodies.
Its first batch development queries found 24 of 24 expected items at
rank one. Fresh second- and third-batch queries found 14 of 24 and 13
of 20 at rank one, respectively, while five unrelated controls per batch
abstained. The [combined saved evaluation](../../artifacts/first-party-harness-candidates-2026-09-22/CROSS-BATCH-SEARCH-EVALUATION-INITIAL-2026-09-22.json)
found the expected item first for 47 of 68 and in the first three for
51 of 68, with 15 of 15 unrelated controls returning no match. Save the
misses. This is local English-language reviewer search with one expected
item per query, not hosted retrieval or a customer relevance benchmark.
S-6.32 needs a new held-out population and a measured no-answer policy;
tuning on these same saved queries would not establish generalization.

## Broader file kinds and placement

The owner clarified that harness intelligence is not limited to Markdown
skills. The [file-kind research](../research/HARNESS-INTELLIGENCE-FILE-KINDS-AND-ADMISSION-2026-09-22.md)
includes root instructions, skills with scripts and assets, agent
profiles, executable tools, protocol configuration, plugins, client
settings and selected reference files. Presence in a work directory is
not native discovery. The [placement report](../research/NATIVE-HARNESS-INTELLIGENCE-PLACEMENT-2026-09-22.md)
maps versioned client paths and isolated home/configuration scopes.
Codex 0.155.1 reads `AGENTS.md` by default; a
[no-model probe](../../artifacts/harness-intelligence-format-pilot-2026-09-22/context/CODEX-MD-CONFIGURED-FALLBACK-2026-09-22.json)
found that `CODEX.md` loads only after an explicit fallback setting.

The [mixed-format pilot](../../artifacts/harness-intelligence-format-pilot-2026-09-22/README.md)
has **six logical candidates**: two native instruction templates, three
skills with real Python scripts, and one local protocol connection with
Codex, Claude Code and OpenCode configuration alternatives. It remains
candidate-only. Its [dated check](../verification/MIXED-FORMAT-HARNESS-INTELLIGENCE-CANDIDATE-QA-2026-09-22.md)
records the exact manifest and remaining gates. The instruction
templates require typed placeholder
rendering; only Codex had a no-model exact-file discovery observation.
The protocol server's Python client negotiated `2025-11-25`; a clean-home
OpenCode attempt with generic `python3` failed from a missing dependency,
while a separately provisioned pinned interpreter connected in a
successor no-model probe. Its canonical config still needs a runtime
provisioner, client trust, and an exact native load check. The new
`2026-07-28` protocol remains unqualified for that candidate.

The three Python utilities underwent independent adversarial review.
Initial tests missed ancestor symlink traversal, a JSON numeric
precision collision, FIFO blocking, and unbounded line or directory
entry work. Their author repaired those cases; 40 focused tests pass,
and an independent rereview replayed the original failures against the
current bytes without finding a new candidate-retention blocker. The
[mixed-format manifest](../../artifacts/harness-intelligence-format-pilot-2026-09-22/manifest.json)
now binds 52 physical source, rendering and review files, while the
[logical candidate catalogue](../../artifacts/harness-intelligence-format-pilot-2026-09-22/candidate-items.json)
contains six packages. **Recheck exact scripts, review-note digests,
generated-cache exclusion and the manifest before any admission.**
Runtime authority, mount provenance, concurrent snapshot consistency and
native invocation remain unqualified.
