## The 100,000-package SaaS boundary

The [dated synthesis](../research/SAAS-AND-HUNDRED-THOUSAND-EXECUTION-GATES-2026-09-22.md)
maps the owner's larger target onto existing roadmap work. Current AGENTS.md
and S-6.40 define the milestone as **100,000 distinct approved logical
packages** in the active release. Report unique eligible harness files as a
separate count; the user's file wording is not a licence to count copied
client layouts or tests. The corrected
[supply analysis](../research/HUNDRED-THOUSAND-HARNESS-INTELLIGENCE-SUPPLY-2026-09-22.md)
shows that, at assumed 50% approval and 80% precheck yield, the package
target needs about 250,000 drafts, 200,000 review candidates and 600,000
per-item reviewer decisions before retries. Qualified batch decisions may
take fewer physical model calls; these are scenarios, not observed
throughput or model authority.

The [offline 100,000-row probe](../../artifacts/hundredk-serving-probe-2026-09-22/README.md)
found a 122 MB synthetic manifest against a 2 MB loader limit, a 73 MB
unpaged list against a 262 KB response ceiling, and a 48.57-second,
2.10 GiB fresh Retriever build per request against the documented
30-second request deadline and 2 GB Fly Machine memory. The fixture had
one fake primary file per row, no real body, and no active approval. A
persistent release index, paged metadata, sparse grant policy and complete
multi-file delivery are serving requirements, not cosmetic capacity changes.
The [live customer audit](../verification/SAAS-LIVE-READINESS-AND-CUSTOMER-JOURNEY-2026-09-22.md)
