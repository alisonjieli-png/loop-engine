## First code batch

The public redirect repair is limited to credential-free public website GET
and HEAD requests on six admitted `www`/apex pairs. A successful public HTML
response can redirect to the same brand's apex with its path and query
preserved. API, MCP, OAuth, authentication, account and browser-state routes
remain origin-local. Credential headers, callback query names, non-read
methods and responses setting cookies are excluded.

This repair does not migrate browser storage. HTTP cannot observe an existing
session in `sessionStorage` or `localStorage`, or a URL fragment. A public-home
visit can reach an apex that appears signed out while the `www` session stays
untouched. Complete signed-in navigation continuity is not claimed.

The browser checker reads visible readonly input and textarea values as well
as visible text. It compares the exact declared MCP URL, rejecting lookalike
paths, other origins and hidden values. It also retains each request's failure
and observed status; a later successful request cannot erase an earlier one.
These checks address the release 92 connection-text and media-accounting
limitations without rewriting those earlier reports.

The source inventory changes add bounded traversal and preserve partial-state
and unresolved-authorship information through seed consumers. Access to a
source directory is not a declaration that its contents may be redistributed.

The roadmap reconciliation adds only the narrow redirect, systems-portal and
matched-benchmark subtasks. Existing task identifiers and dated evidence remain.
Generated tracker and continuation views still come from the existing roadmap.
