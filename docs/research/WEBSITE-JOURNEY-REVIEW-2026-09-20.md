# Website journeys and positioning review

Kind: dated public-source comparison. Observed September 20, 2026.
This extends the September 18 feature matrices without changing their cells.
It does not qualify a competitor's implementation or rank conversion rates.

## Findings

The clearest opportunity for Baltor is a shorter path from a useful promise
to an inspectable result. Additional pages help only when they complete that
path. A large feature table cannot compensate for unfinished registration,
an unclear connection or an example that the visitor cannot run.

The review covers all nineteen identified companies in the original matrix,
four adjacent website references and the deployed Baltor pilot. Overmind and
Lemma remain unresolved identities. They were not scored as missing features.
The [population](WEBSITE-COMPARISON-POPULATION-2026-09-20.json),
[review notes](WEBSITE-REVIEW-NOTES-2026-09-20.json) and
[browser observations](../../artifacts/architecture-audit-2026-09-19/public-websites-1.json)
retain the exact scope, source addresses and observation times.

The main development HTML contains a filterable comparison of observed start,
documentation, pricing, security, example and operations links. A visible link
means only that the sampled page exposed it. Unknown means the sample did not
establish it. Neither label establishes whether an authenticated flow works.

## Lessons from the closest design references

| Reference | Observed public pattern | Application to Baltor |
|---|---|---|
| [SenseLab](https://www.sense-lab.ai/) | Bright first screen, short learning benefit, clear start action and product preview | Retain a light visual system and short route into setup. Use our own copy and evidence. |
| [Mem0](https://mem0.ai/) | Developer integration example close to the primary promise; pricing, documentation and trust links | Give visitors a usable first example, not only an architecture explanation. |
| [Zep](https://www.getzep.com/) | Separate developer-start and demonstration-booking actions; product view and enterprise controls | Keep self-service setup distinct from a future enterprise sales conversation. |
| [Supermemory](https://supermemory.ai/) | Copyable setup prompt and persistent documentation navigation | Supply reviewed, version-specific configuration without embedding secret values. |
| [Stripe documentation](https://docs.stripe.com/mcp) | Client-specific connection instructions, access management and action confirmation | Explain setup, verification and revocation in one journey. |
| [LangWatch](https://langwatch.ai/) | Problem-led introduction and visible evaluation interface | Show what was checked and what the result establishes. |
| [n8n](https://n8n.io/) | Workflow-led language, visible control and concrete customer-story links | Explain reusable solutions through tasks. Publish our own qualified examples before making equivalent claims. |
| [Retool](https://retool.com/) and [Resend](https://resend.com/) | Documentation, examples and trust/operations routes support the main action | Complete a practical first-use path and keep operating information easy to find. |

Eight desktop screenshots were inspected, including Baltor. Remaining sites
were reviewed through rendered headings and visible links, not a visual design
assessment. Two 390-pixel overflow observations, on LangWatch and Stripe's
documentation, remain narrow observations. They are not a general accessibility
verdict or evidence that Baltor has a better complete experience.
The browser inventory retained at most ninety visible links and twelve
secondary headings per page. It did not open every navigation menu or follow
every linked destination. The Baltor screenshot records the deployment before
this cycle's new setup pages; newer delivery evidence is in the checkpoint.

## Measurable targets for Baltor

| Customer job | Target and check | Current gap |
|---|---|---|
| Understand the benefit | A new reader can name the task, intended reusable output and practical benefit without learning runtime vocabulary | Requires real reader testing; internal copy review is not a conversion study. |
| Connect a client | Secret-free configuration, explicit compatibility, real protocol check and actionable refusal | Browser protocol testing is distinct from native loading and completed task qualification. |
| Try useful intelligence | Search, inspect, select and fetch an exact revision; record the observed outcome | The hosted population is a diagnostic example, not a complete commercial catalogue. |
| Trust a reusable component | Inspect provenance, license, contracts, effects, tests and independent qualification | Candidate references must not be advertised as active reviewed packages. |
| Control account access | Sign in, recover, revoke and understand usage without operator intervention | Public identity and email journey still requires runtime integration. |
| Buy and stop paying | Clear price, real test checkout, reconciled subscription state, cancellation and access changes | Operator Stripe access does not qualify backend billing. |
| Judge improvement | Compare held-out tasks, failures, complete cost and quality before promotion | No measured pilot-level token savings or daily learning benefit is established. |
| Use the interface comfortably | Keyboard controls, narrow screens, enlarged text, clear loading/error states | Browser checks cover declared cases, not every device or assistive technology. |

## Proposed go-to-market sequence

Start with an invited developer who already has a supported client and one
repeatable task. The first useful result should demonstrate reviewed material
or reusable code contributing to an independently checked output. Measure
time to connect, time to the first accepted result, repeated-task utility and
complete task cost. Do not substitute sign-up counts or homepage traffic for
those outcomes.

After that journey works, publish a short task example with exact versions,
limitations and a runnable check. A showcase should name the accepted solution
and the conditions under which reuse works. Broader audience pages, search
marketing and enterprise claims should follow evidence rather than expand an
unfinished promise. No outreach, advertising spend or customer data collection
was performed for this review.

## Review limits

The browser opened public pages without signing up, paying, submitting forms
or using competitor credentials. It did not benchmark competitor retrieval,
test their native clients or verify their customer numbers. Marketing claims
remain claims. Current public pages also do not silently revise dated license,
repository or benchmark findings in the original comparison.

The desired outcome is a better complete customer journey. Overall superiority
is not established by this review and is not a release claim.
