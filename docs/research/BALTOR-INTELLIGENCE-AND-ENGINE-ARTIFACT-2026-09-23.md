# Baltor intelligence and engine research artifact

Kind: component-specific research companion for Claude Code, September 23,
2026. This covers the proposed 100,000-package library, retrieval, model
choice and component engines. The [roadmap](../roadmap/roadmap.yaml) remains
the task authority. The [supply analysis](HUNDRED-THOUSAND-HARNESS-INTELLIGENCE-SUPPLY-2026-09-22.md)
holds assumptions and throughput math; this artifact names the interfaces
and evidence the library needs.

The [complete behavioral explanation](../../ASTRA.md#complete-behavioral-explanation)
defines the discrete cognitive or act step Loop node. Its fresh harness

plugin, reviewer, model adapter or sandbox is an internal mechanic or

## Intelligence identity and count

    Persistent intelligence layers
    ├── Context Intelligence
    ├── Code Intelligence
    ├── Runtime History and Solution Intelligence
    └── User Feedback Intelligence

    Intelligence families
    ├── Loop-native intelligence
    ├── Harness intelligence
    └── Open Knowledge Format intelligence

Harness intelligence is the family built to follow an external harness, not
a fifth layer or a synonym for Markdown. Its package may contain root or
scoped instructions, Agent Skills with scripts, reference assets,
deterministic tools, subagent and command profiles, hooks, plugins, settings
and protocol connection files. A file's extension does not grant effects or
prove native discovery. A body already owned by Code Intelligence cannot
be copied into harness-local solely to raise a count.

The [current repository rule](../../AGENTS.md#decisions-that-stand-until-the-owner-changes-them)
sets the first milestone at 10,000 and the target at **100,000 distinct
approved logical packages in the active release**. Report unique eligible
canonical source files, rendered client variants, physical image files and
native-loaded files as separate counts. One skill with scripts is one
package; the same method for several occupations, clients, languages or
models is not several packages without a different method, effect or
acceptance condition. Every counted package needs independent exact-tree
approval, source rights, a complete digest-readable tree, an active release
binding, search visibility to an eligible account and at least one
qualified native placement. Count from records, not a directory scan or a
generator's output.

The hosted baseline is 43 single-Markdown bodies, none named SKILL.md or
carrying Agent Skills frontmatter. Four original batches now hold 80
candidate native Agent Skills, while two heterogeneous pilots hold nine
more candidate packages. None of those 89 was admitted, granted, natively
used or shown to improve a customer task. The [candidate handoff](../context/CODEX-SIDE-RESEARCH-HANDOFF-2026-09-22.md)
binds exact manifests, independent static quality assurance and failures.

## Source-to-release factory

    Pin a real task need or permitted exact source
    ├── Record source revision, rights and provenance
    ├── Define one distinct method, typed input/output, effects and stop rule
    ├── Search active and candidate methods for reuse or duplication
    ├── Author the few native files the method actually needs
    ├── Run format, path, secret, dependency and known-wrong checks
    ├── Obtain independent risk-calibrated exact-tree decisions
    ├── Stage immutable bytes and a versioned release
    └── Measure search, pickup, task use and independently accepted work

Original first-party methods grounded in verified code, observed customer
misses and pinned occupational tasks are the first lane. Public skill
directories, repositories and the official protocol registry are discovery
or later rights-cleared lanes, not redistribution grants. The pinned O*NET
inventory has 18,838 task rows, fewer than 100,000 and not all useful
digital methods. An external licence badge cannot clear nested files or
mutable remote behavior. Unknown rights or source revisions hold a
candidate. Shallow rewriting of protected expression does not establish
originality. Publisher submissions and partnerships can provide explicit
distribution rights and updates, but must meet the same file-level checks.

The three-reviewer proposal under S-6.63 requires decisions from different
model families than the producer. A model vote alone is not approval:
calibrate on frozen benign and malicious controls, audit blinded real
decisions by risk class and escalate high-consequence code or ambiguous
rights to a person. A batch call can yield several per-item decisions only
when each exact tree was demonstrably inspected. At hypothetical 50%
approval and 80% deterministic-precheck yield, the 100,000-package target
implies about 250,000 drafts, 200,000 review candidates and 600,000
per-item reviewer decisions, before retries and withdrawal. Those rates
and physical calls have not been measured. Run a stratified 1,000-candidate
pilot before committing to a scale schedule.

## Serving and engine edges

Search returns small typed references and has a relevance floor. It does
not load every body into a harness. The active release's index is a
rebuildable projection, not a second source of rights or approval.
Eligibility and tenant policy apply before ranking, and exact grants and
withdrawal are checked again before bytes leave the server. The
[100,000-row probe](../../artifacts/hundredk-serving-probe-2026-09-22/README.md)
shows the current per-request index build and unpaged listing cannot scale.
Persist a qualified search index per release, use bounded pages, and
measure held-out task phrasings, alternative relevant methods, no-answer
behavior, effect filtering, cold and concurrent latency, memory and
withdrawal races. The four-batch local candidate search put the expected
item first for 56 of 80 author-written task phrasings, in the first three
for 60 of 80, and abstained on 20 of 20 unrelated prompts. This is
reviewer triage, not hosted relevance evidence.

Every functional component has a fixed typed versioned edge with
eligible, swappable engines behind it. An engine declares capabilities,
effects, dependencies, lifecycle and cost; evidence can rank qualified
choices without silently changing a step's authority. Harness execution,
search, retrieval, context selection, model routing, one-model-versus-
several-model strategy, sandbox and verification can vary independently.
The [composition research](CONTAINER-AND-ENGINE-COMPOSITION-2026-09-22.md)
and [architecture direction](../architecture/LAYERED-HARNESS-WRAPPERS-AND-NATIVE-CONTROL.md)
give the proposed boundaries. External harnesses such as Codex, Claude
Code, OpenCode, Pi and ZCode are candidates for a qualified executor
adapter, not forks to ship by default. [ZCode research](ZCODE-AND-HARNESS-INTELLIGENCE-MARKET-REVIEW-2026-09-22.md)
still marks its integration unqualified.

The [model-conditioned research](MODEL-CONDITIONED-HARNESS-INTELLIGENCE-2026-09-22.md)
permits simplified or condensed renderings for an exact model and task
only as versioned derivatives bound to the reviewed canonical method.
They do not add package count or grant broader effects. Context budgets,
model output capacity, selected allowance and total-run authority remain
separate. Unknown cost and provider usage stay unknown.

## Proof that matters to customers

The current competitor review (kept in the owner's private research folder, outside this public repository)
finds native skill installation and large searchable directories already
available. Catalogue size alone is a supply milestone. A paid advantage
is a hypothesis until a customer can find a relevant exact package, inspect
its rights and effects, place it in their chosen harness, use it on a
focused step and produce accepted work under the same model and budget.
Compare native harness alone, manual equivalent selection and
Baltor-selected material on frozen tasks with an independent evaluator.
Preserve misses, refusals, harms and excluded runs. Report accepted work,
elapsed time, physical calls, customer model cost and review effort.
