# A supply path to 100,000 harness intelligence packages and their files

Kind: dated research and conditional scale design, September 22, 2026 local time. This responds to the owner's 100,000-file goal and clarification that harness intelligence can be any file a harness discovers, loads or invokes in its working environment. The current [repository rule](../../AGENTS.md) and [S-6.40](../roadmap/roadmap.yaml) record the milestone as **100,000 distinct approved logical packages**, each containing one or more harness-readable files. We report the unique eligible file count separately so the owner's file goal stays visible. This report is not an admission decision, model allowance, release or second roadmap. No provider was called and no candidate was approved or promoted for this report.

## Count packages and files separately

The recorded milestone is **100,000 distinct approved logical packages in the active release**, each customer-retrievable and native-materializable in at least one supported client. Separately count unique approved installable source-file identities. Every file has a recorded digest and purpose inside a package whose approval binds every delivered file digest and the complete tree digest. Count a source file once even if it has several client layouts, copies, releases or model renderings. Collapse identical bytes copied across layout variants and inspect near duplicates before they contribute to either count. A file's presence does not prove client discovery or use.

| Measure | Boundary |
|---|---|
| Candidate packages and files | Draft or imported material awaiting rights, format, safety, distinctness and independent decisions; no headline credit. |
| Approved active logical packages | The recorded 100,000 target: distinct task methods or capabilities in the current release. `SKILL.md` plus its scripts and references is one package. Role, company, language, harness and model labels do not multiply it. |
| Approved active installable payload files | A separate count that tests the owner's file wording. Count substantive source-file identities once, with customer retrieval and supported native materialization proved. Exclude review notes, test-only fixtures, CI scripts, source snapshots, caches, inactive versions, copied client layouts, repeated boilerplate and files made to inflate the count. |
| Rendered variants and physical image files | Count all client-specific copies, model renderings and build outputs separately from unique approved source files. |
| Customer-findable, offered and fetchable packages | A permitted account can find an item by identity and task, be offered it under a current entitlement, and read its exact complete package after a current grant check; record each fact separately. |
| Placed, discovered, loaded, used, verified and helpful | Separate observations in a clean native harness. “Helpful” needs matched task outcome evidence against a no-package baseline. |

The current baseline is **43 hosted single-Markdown items**, whose eligibility under this stricter native-file definition still needs checking. Four isolated batches hold **80 original text-only Agent Skill candidates**. The [first mixed-format pilot](../verification/MIXED-FORMAT-HARNESS-INTELLIGENCE-CANDIDATE-QA-2026-09-22.md) has **six logical candidates** and 52 manifest files, but those files include tests, notes and alternative client renderings. A [second multi-file batch](../verification/SECOND-MIXED-FORMAT-CANDIDATE-BATCH-QA-2026-09-22.md) adds three candidate skills with scripts. None of these 89 candidates is admitted or a measured customer benefit. The [first-party research](FIRST-PARTY-TEN-THOUSAND-HARNESS-PACKAGES-2026-09-22.md) and [file-kind guide](HARNESS-INTELLIGENCE-FILE-KINDS-AND-ADMISSION-2026-09-22.md) explain the 10,000-package milestone and format gates.

## Runtime and file taxonomy

```text
Operational runtime type
└── Loop
    ├── Operational relationship: Starting, Spawned by, Queried by,
    │   Retrieved by, or Connected from
    ├── Role: Practitioner, Intelligence, or Solution
    ├── Versioned role profile and purpose categories
    ├── Run mode: deterministic, hybrid, or non-deterministic
    ├── Step profile; typed input and output; loop and exit conditions
    ├── Graph relationships; budget, permissions, and effect policy
    ├── Model settings when permitted
    └── Run History records
```

Generation, review, placement, indexing and release are mechanics owned by classified Loops and existing components. Harness intelligence is a family, not a fifth intelligence layer. Do not duplicate a canonical body into another family to raise a count.

| Native file kind | Real payload | Qualification |
|---|---|---|
| Scoped instructions, agents and commands | `AGENTS.md`, `CLAUDE.md`, supported subagent or command profile | Prove scope, client/version discovery and inheritance isolation. `CODEX.md` needs an explicit qualified Codex fallback setting; the filename is not default pickup. |
| Agent Skill package | `SKILL.md` plus only needed `scripts/`, `references/`, `assets/`, schemas or templates | Review every relative file and digest; prove native discovery and on-demand use. The [Agent Skills specification](https://agentskills.io/specification) permits these folders and progressive loading. |
| Tool or reusable code | Python, JavaScript, shell or SQL implementation with input schema and entry point | Prove invocation authority, dependencies, confinement and known-wrong behavior. Presence alone is not invocation. |
| Plugin, hook or protocol connection | Plugin declaration, executable module, client configuration, local MCP server | Check activation, endpoint, tool list, credential reference, dependencies, effects and version negotiation. MCP has different control surfaces for [resources, prompts and tools](https://modelcontextprotocol.io/specification/2025-11-25/server/index). |
| Reference or data asset | Schema, lookup data, example, image or document named by a selected skill or placement plan | Check rights, provenance, scope, size and on-demand read. Arbitrary workspace data is not automatically harness intelligence. |

One method can have one file or several; five files are not five methods. Ten client copies of `SKILL.md` are not ten distinct source files. Do not give authors a file quota; reject an extra file without a specific loader, procedure or acceptance check. The [native placement research](NATIVE-HARNESS-INTELLIGENCE-PLACEMENT-2026-09-22.md) records tested client versions and paths.

O*NET alone cannot guarantee 100,000 packages or files. Even the implausible upper bound of one approved method per task row yields only 18,838 packages; at five eligible files each that is 94,190 files, before removing physical tasks, shared methods or review failures. At three files it is 56,514. ESCO's concepts cannot automatically fill the gap. These are source ceilings, not proposed package designs.

## Repeatable source-to-original-package factory

```text
Pinned task need, verified code or consented customer request
  -> rights and provenance pack with source version and digest
  -> one typed method: trigger, input, output, effects, stop condition,
     acceptance check and known-wrong case
  -> search approved packages and candidate clusters; reuse or reject
  -> choose the fewest files that make the method native and testable
  -> author original instructions, code and resources with producer record
  -> deterministic rights, syntax, path, dependency, secret and effect checks
  -> independent exact-package review of every script and asset
  -> qualified release, native placement probe, authorized search and read
  -> offered/fetched/loaded/used/verified and paired-benefit evidence
```

The candidate manifest needs one logical identity and contract; source IDs and rights; file paths, MIME kinds, sizes, per-file digests and a package tree digest; client/version placement; dependencies and effects; producer; closest existing method; fixtures; independent exact-byte decision; release and withdrawal state. Extend existing candidate, catalogue, grant and release contracts rather than create another source of truth. Store review notes and tests outside installable payload unless independently useful in a customer task with a native read path. Any changed byte needs a new version and review.

The existing [three skill batches](../verification/OCCUPATION-LINKED-HARNESS-CANDIDATE-BATCH-QA-2026-09-22.md) and [mixed-format pilot](../verification/MIXED-FORMAT-HARNESS-INTELLIGENCE-CANDIDATE-QA-2026-09-22.md) are test material, not an active catalogue. The single-Markdown preparer is not a multi-file package factory. The [10,000-item serving audit](TEN-THOUSAND-SEARCHABLE-HARNESS-FILES-2026-09-22.md) found a 2-megabyte manifest loader, single-`.md` builder, per-query index rebuild, unpaged listing and snapshot grants. Supply must qualify serving before it is customer-findable.

## Sensitivity math, not a schedule

Let `P` be the recorded 100,000 approved logical-package target, `p` the measured mean eligible unique files per approved package after duplicate collapse, `a` the approval fraction among candidates sent to independent review, and `d` the fraction of drafts passing deterministic prechecks. Ignoring the unqualified 43-item baseline: review-eligible candidates = `ceil(P/a)`; three independent reviewers produce at least `3 × candidates` **per-item decisions**; drafts = `ceil(candidates/d)`. Physical model calls may be fewer when a qualified reviewer safely decides several exact packages in one call, or more because of retries and disagreements. Call volume, reviewer attention and error by batch size must be measured. The unique-file count is measured directly; `P × p` is only a scenario because files may be shared or deduplicated. This excludes re-review, withdrawals and extra code review.

| Assumed `a` | Approved packages `P` | Review-eligible candidates | Three-reviewer per-item decisions | Drafts if `d=0.80` | Illustrative eligible files if `p=3` and no sharing |
|---:|---:|---:|---:|---:|---:|
| 50% | 100,000 | 200,000 | 600,000 | 250,000 | 300,000 |
| 75% | 100,000 | 133,334 | 400,002 | 166,668 | 300,000 |

These are conditional scenarios. The first six-package pilot cannot estimate `p` because its 52 files mix payloads, tests, notes and copies. The 80 text-only candidates have one source file per package in their present bytes; three newly drafted multi-file skills are too few to estimate a production mix. None measures production `a` or `d`. If `a=0.5`, 200,000 review-eligible candidates would take about 2,000 days at 100 candidates/day, 200 days at 1,000/day, or 20 days at 10,000/day before release and recovery. At 10% human escalation and 15 minutes per escalation, that case adds about 5,000 hours. These are illustrations, not measured staffing or spending authority. Batch review cannot multiply decisions beyond what each reviewer demonstrably inspected. Record every model, prompt, physical call, per-item decision, usage, outcome and human minute under a declared ceiling.

A stratified 1,000-candidate pilot must measure source-lead-to-distinct-method conversion, precheck pass, approval yield, eligible files/package, error by risk, provider throughput, native pickup, search relevance and helpfulness. If the observed mean is one unique eligible file per package, the 100,000-package target would also yield 100,000 unique files; do not invent resources to change that ratio. Rights-safe approval may precede measured benefit, but label benefit unmeasured.

## Testable gates and stopping rules

| Gate | Check and stop rule |
|---|---|
| Source and distinctness | Pin source and file-level right. Hold unknown rights, missing revision or protected expression. Reject a package when its contract, effects and verifier match an existing method and only role, company, language, harness or model changes. Record unique-needs denominator per source stratum. |
| Exact bytes | Refuse path escapes, hidden executables, missing dependencies, secrets and changed digests. Frontmatter validation proves format only. Execute positive and known-wrong checks in a bounded sandbox; connection packages need native handshake under scoped authority. |
| Independent review | Producer cannot approve its own bytes. Freeze benign and malicious challenges, then adjudicate blinded random samples of actual approvals and refusals by source and risk. One critical false approval freezes its tranche for root-cause repair. Zero defects in 300 random samples gives only about a 1% one-sided 95% upper bound in that stratum, not zero risk at 100,000. High-consequence code, ambiguous rights and mutable remote effects need human decisions. |
| Marginal supply | After the 1,000-candidate pilot, predeclare a minimum distinct-approved yield and unmet-need coverage for each source lane. If two consecutive 200-lead batches yield under 10% distinct approvable methods, pause and investigate demand or duplication. Ten percent is a proposed investigation trigger, not a measured threshold. |
| Release and retrieval | Only approved active exact versions enter an immutable release. Withdrawal must survive rollback. Every identity must be findable and every granted package digest-readable in an isolated host. Held-out task and no-answer queries, tenant isolation, p95/p99 latency, memory and live-hostname checks precede a size claim. |
| Native and customer outcome | For each supported client/version and kind, prove clean-home placement, discovery and activation without inherited material. Measure selected-file use and independently checked task work separately; paired no-package trials establish incremental benefit. Copying a file to disk is not a loaded result. |

Publish bounded tranches with logical package count, eligible unique source-file count, rendered-variant and physical-image-file counts, duplicate-collapse count, withdrawals, rights holds, review decisions, findability, offered and fetched counts, and native placed, discovered, loaded, used and verified records bound to one manifest digest. Use the first 1,000 to forecast throughput and cost, then qualify the 10,000-package milestone before proceeding toward 100,000 approved packages. If there are too few distinct needs or useful multi-file packages, report the gap rather than meeting the number with Cartesian variants.
