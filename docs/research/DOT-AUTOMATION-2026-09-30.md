# Dot research and user-testing integration

Kind: current-source research and read-only schedule audit; no dot connection or schedule installed.

Use a dot as an additional researcher and explicit UI tester, while the
existing Loop Engine scheduler remains the owner of durable work dispatch,
review and publication. Do not build a second runtime or give an agent raw
production database credentials.

## What a dot can contribute

Official documentation describes proactive research as reading and private
notes, not browser/app actions. Acting through connected apps or a browser
belongs in an explicitly assigned or saved scheduled task. Cloud and local
computer sessions are distinct, and a local connection must be available.
Pausing the main task, stopping delegated work and cancelling a schedule are
different controls. See [tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory),
[computers and apps](https://learn.chatgpt.com/docs/dots/computers-and-apps)
and [controls](https://learn.chatgpt.com/docs/dots/controls). The owner's account
availability and actual permissions have not been inspected.

A bounded first assignment can research changed competitor features, relevant
investor theses, creators/influencers, new MCPs and implementation strategies.
Preserve primary links, publication and observation times, source versions,
claims versus observations, rights, uncertainty and concrete test proposals.
Finding a lead never authorizes outreach, spending, execution or publication.

## Ordered implementation after OAuth

1. Expose account-scoped work requests, submissions and status through a
   versioned API/MCP edge backed by existing managed records. The dot reads
   tasks and uploads findings; Baltor returns validation, review and repair
   status. Keep research-write permission separate from read/download access.
2. Accept bounded files into untrusted staging with digests, MIME/size limits,
   ownership, provenance and explicit permitted use. No automatic execution,
   database writes outside that account, admission or public serving follows.
3. Run an explicit ordinary-account browser task: sign in, search, inspect,
   retrieve and verify exact bytes. Record latency, failing request references,
   screenshots and expected versus observed behavior. Use staging for admin
   tests and never fabricate customer traffic or engagement.
4. Trial seven days of bounded research with a proposed ceiling of ten changed
   leads and three work requests per day. Measure useful discoveries, accepted
   fixes, duplication, cost, gaps and failure rate before installing recurrence.
5. Publish only independently reviewed components and evidence-backed claims.
   Review applicable notice/retention coverage before storing new personal data.

OAuth only establishes delegated access. It does not mean those upload,
two-way queue or scheduled-task capabilities are already implemented.
