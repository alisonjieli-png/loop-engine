# Plan and execution boundary

Planning and execution use the same Loop runtime but have different authority.

```text
Practitioner planning Loops
├── preserve the original task
├── inspect current state
├── classify ambiguity
├── define evidence and task slices
├── propose dependencies and safe waves
└── produce a passive PlanDefinition
        ↓
independent Plan Assurance Practitioner
        ↓
accepted plan compiles to LoopGraphDefinition
        ↓
Practitioner, Intelligence, and Solution Loops execute
```

A plan is not a runtime or graph authority. Execution begins only when its
planning authority profile permits it and required assurance passes.
