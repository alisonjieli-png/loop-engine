## Search result that should govern the next experiment

The first batch's local SQLite full-text search placed the expected item
first for 24 of 24 pilot queries after development. To test whether that
rule generalized, an independent reviewer wrote 24 new task phrasings
for this second batch before searching it. The expected candidate ranked
first for **14 of 24** and within the first three for **16 of 24**.
Eight relevant queries missed, including inventory availability,
fulfillment quantities, record flow, field lineage, sales promises,
acquisition channels, interview synthesis and native placement. Five of
five unrelated queries returned no match. This is a small English-language
pilot with one expected item per query, but it is enough to reject a claim
that the current lexical search reliably finds new candidates.
The [frozen query population](../../artifacts/first-party-harness-candidates-2026-09-22-wave-2/search-probes.json)
and [saved initial evaluation](../../artifacts/first-party-harness-candidates-2026-09-22-wave-2/SEARCH-EVALUATION-INITIAL-2026-09-22.json)
retain every hit and miss, with the manifest and search-tool digests.

Keep these failures with the successful first batch. Do not tune the
current threshold against all 48 queries and then call those same queries
an independent evaluation. Freeze the 48 as development and regression
material, then evaluate the next unseen batch. Compare at least metadata
only, selected native body text, author-supplied search phrasings and a
qualified hybrid or semantic engine under the same no-answer, grant and
cost conditions. Query aliases are discovery aids, not proof of relevance.
The local tool is for reviewer triage and cannot become the hosted index
or a permission decision.
