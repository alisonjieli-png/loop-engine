# Configuration and native initialization experiments, 2026-09-12

The study made 70 real model calls through Tactical Engineering using
`gemma-4-coding-abliterated`. The forty-cell repair comparison passed 159 of
160 case checks. Thirty-nine cells passed every case. Nine separate native
Markdown initialization controls passed across Pi, OpenCode, and Codex.

The audit verified 244 saved Run History chains and reconciled all 70 physical
calls against the observation records. Provider-reported usage was 137,960
input tokens and 7,828 output tokens. Accounting is complete for this study;
monetary cost remains unknown. Automatic provider failover was disabled.

These are component experiments on four disclosed repair cases and synthetic
initialization markers. They do not establish unseen-task performance,
retained learning, or a full-system benchmark. The complete meaning of
"discrete cognitive or act step Loop node" remains in the final section below
and in the [terminology handoff](../context/DISCRETE-COGNITIVE-OR-ACT-STEP-LOOP-NODE-HANDOFF-2026-09-12.md).

## Applied repair and resource configuration

Each cell received four rejected arithmetic-tool requests, their current
requirements, the exact tool argument contract, and a fixed menu of candidate
replacements. The model selected a replacement for each case. Loop Engine
applied the selected request and invoked the registered pure tool. A separate
deterministic verifier compared its actual result with controller-owned
expected values.

The cases cover stock after shipments, combined hours, units in packages, and
a balance that may become negative. They are small disclosed controls. The
replacement menu includes both correct and incorrect candidates. Structural
admission of the model's selection does not make its selected tool request
valid or its result correct.

implementation is a real deterministic application registered through the

## Information passing, skills, and tools

The reference variant presented 17 small resource descriptions, including five
relevant resources. A model selected references. A newly launched consumer
process resolved the exact stored bindings through `InformationResolver`,
then supplied the selected material to the next model assignment. Each of the
four consumers returned 1,463 bytes of serialized material and reported no Tactical credential in its
environment. Scope and missing-permission controls refused access in the
offline tests.

Serialized full experimental history contained 11,415 bytes. Reference delivery reduced
the material passed to the final assignment, but the selection call and
reference metadata increased total input tokens for this small population.
The four reference cells consumed 25,160 input tokens, compared with 14,166
for full history and 6,998 for relevant inline context. This round does not
demonstrate a token saving from references.

The skill variant used the existing
`software-tdd-red-green-refactor@1.0.0` file. A separate
`practitioner.verifier@1.0.0` assignment reviewed its exact manifest and
provided supporting source quotations. The controller checked those
quotations before creating a `SkillAdmissionRecord`. Each skill cell loaded
the body through `SkillRegistry` for task use. Admission was confined to the
study's registry. The same Tactical model performed the review; this does not
establish strong adversarial independence or promote persistent intelligence.

Default tool declarations came from actual registered-tool discovery. The
forty-cell matrix used Loop Engine to invoke those tools. Native harness tools
and native plugin execution stayed disabled. Original adapter contracts still
refuse direct `context_refs`, `tool_refs`, and `skill_refs` requirements, and
their configuration loaders refuse added initialization or plugin fields.
The separate native experiment below uses explicitly registered adapter forks.

## Native Markdown initialization

The native experiment reused each installed harness with a pinned initializer
inside its existing confined workspace. It compared an absent file, a seeded
`AGENTS.md`, and the same seeded file with its loader disabled. The random
expected marker appeared only in the initialization artifact. A pre-dispatch
check verified its absence from the assignment and response schema.

| Harness | Seeded file, loading enabled | File absent | Seeded file, loader disabled |
|---|---|---|---|
| Pi | Returned the exact marker | Returned `not_available` | Returned `not_available` |
| OpenCode | Returned the exact marker | Returned `not_available` | Returned `not_available` |
| Codex | Returned the exact marker | Returned `not_available` | Returned `not_available` |

All nine calls had complete accounting. The original adapter configurations
were unchanged. The experimental forks kept the existing provider route,
tool denial, private gateway, and process confinement.

Codex startup discovery and its byte-limit setting were checked against the
[official OpenAI documentation](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
The OpenCode configuration used its documented
[instruction-file mechanism](https://opencode.ai/docs/rules/).
Pi's installed 0.85.1 resource loader and argument parser supplied the pinned
implementation reference. The live controls, rather than documentation alone,
establish the narrow loading result above.

This experiment qualifies native Markdown visibility in these registered
forks. It does not qualify native tool execution, arbitrary plugins, skill
scripts, a persistent harness pool, or an unrestricted working directory.

their exact frozen source archives. No production package source was changed
by this study, and the earlier full installed suite was not rerun.

Two native-requirement diagnostic launches failed during request construction:
one omitted an output role, and one used a non-dispatch flag in a request type
that requires model authority at construction. Both made zero model calls.
Their failure records remain alongside the corrected diagnostic result.

This round establishes bounded repair application and resource-loading
mechanisms. The earlier failed adaptive task remains a separate unresolved
result. Larger task populations, full native tool and plugin integration,
continued alternative production, and verified learning transfer need their
own experiments. No commit or publication was performed.

## Complete behavioral explanation

A discrete cognitive or act step Loop node is an independently governed
instance of the Loop runtime responsible for one clearly defined cognitive
step or action. A cognitive step might interpret information, identify a
missing requirement, compare alternatives, or evaluate a result. An action
might inspect a directory, build software, execute a test, create an artifact,
or send an authorized email.

Each discrete cognitive or act step Loop node receives the context,
instructions, skills, plugins, tools, and working files relevant to its
assignment. Essential information can be supplied directly, while additional
information can remain in centralized storage behind authorized, versioned
references. It does not automatically need the entire task history or every
available tool.

A separately initialized harness process, such as OpenCode, Pi, Codex, or a
custom implementation, can perform the assignment. When explicitly permitted,
another harness can attempt the same assignment after a failure. The
assignment's contracts, permissions, history, and remaining authority persist
across those attempts.

Discrete describes the scope of the assignment, not a restriction to one
attempt, one model call, or one output. A discrete cognitive or act step Loop
node can examine whether an observation matches its expectations, identify a
problem, repair or change its approach, and repeat until its declared
completion conditions are satisfied.

Alternatively, a discrete cognitive or act step Loop node can publish an
initial candidate output and continue working while its continuation
conditions and authority permit. It can produce additional alternatives over
time, including alternatives that are better, worse, or useful under different
circumstances. Consumers must identify exactly which output they used.
Publishing an output does not necessarily mean that the producing assignment
has finished.

For externally consequential actions, continued operation does not authorize
repeated effects. For example, generating alternative email drafts can
continue, but sending an email requires its own authorization and protection
against duplicate delivery.
