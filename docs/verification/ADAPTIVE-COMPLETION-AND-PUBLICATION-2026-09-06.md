## Completion follows the declared gates

`HostRuntimeBinding.completion_verifiers` is an optional frozen tuple. After
the primary verifier confirms completion, every configured extra gate must
also pass through an independently registered endpoint and exact-effect
approval. Failure, unavailable evidence, changed state, or a malformed result
prevents completion. No gate becomes a model-selectable operation. Bindings
without extra gates retain version 1 behavior and make no additional calls.

The arithmetic example generates source-independent cancellation cases and
qualifies their expected results with integer arithmetic and a separately
implemented, input-sized Decimal calculation. In a real pinned Python
container, the previously accepted Sales source passed its 32 fixed checks but
failed 6 of 18 extra cases. The new gate returned `task_complete=false`.
The authored reference passed 32/32 and 18/18. The original failed source was
not changed. These are finite counterexamples, not proof over every input.

The repair loader reads an explicitly selected failed observation through
existing Runtime History Intelligence and artifact contracts. It checks the
task, source, scope, committed history, and artifact digest before exposing a
bounded summary under a separate disclosure grant. Historical acceptance is
never inherited. Offline tests cover this loader; a live assisted/fresh
improvement has not been demonstrated.

```text
Operational runtime type
└── Loop
    ├── Relationship: Starting, Spawned by, Queried by, Retrieved by, Connected from
    ├── Role: Practitioner, Intelligence, or Solution
    ├── Exact versioned role profile
    ├── Purpose and domain categories
    ├── Mode: deterministic, hybrid, or non-deterministic
    ├── Step profile and typed input/output contract
    ├── Loop and exit conditions
    ├── Graph relationships
    ├── Budget, permissions, and effect policy
    ├── Model settings when authorized
    └── Run History
```

`adaptive_spawned_assignment/v1` carries stable task identities, prerequisites,
input bindings, and an output contract. The existing plan compiler checks the
whole dependency set before dispatch. Delivery uses finite JSON values or
body-free references through the Information Resolver and typed Loop ports.
Only completed, unchanged producer results can satisfy a dependent input.

The public adaptive fixture deliberately lists the consumer first. Execution
orders the producer before it and passes `[2, 3]` to produce `5`. Malformed
schemas, cycles, missing producers, incompatible ports, mutated results, and
unauthorized materialization are refused. Subproblem success does not certify
the spawning task. Execution remains serial; this change does not introduce
parallel Practitioner scheduling or an alternative runtime.

## Restart and cancellation

An expired unstarted lease may return to admission under its existing attempt
policy. An expired running activation enters dead letter with
`RUNNING_OUTCOME_UNKNOWN_RECONCILIATION_REQUIRED`. Process-death tests confirm
that an already performed fixture effect is not repeated. This does not prove
power-loss durability, distributed exactly-once effects, or automatic
reconciliation.

A required `ReactiveHistoryPolicy` saves and reopens committed canonical Run
History before publishing a successful activation. The reference binds its
definition, series, trigger, input, attempt, fence, terminal event, history
head, and consumed approval record. Missing persistence is explicit; default
handlers do not silently acquire write authority. Older activation records
remain distinguishable through the exact version 1 reader.

Cancellation is terminal. A late handler return cannot accept output, start a
fallback, or spawn further work. Known model usage remains recorded. A kernel
preparation that already terminated cannot be relabeled after its returned
projection fails validation; preparation still fails and returns no usable
result. The tests check both facts separately.

## Documentation, installation, and demos

The review covers Markdown structure and local links across the publishable
corpus, plus targeted semantic review of current setup, host, reactive,
example, context, and benchmark guides. It is not a fresh fact-check of every
historical sentence or every remote URL. Historical failures and test counts
remain dated rather than rewritten as current successes.

The structural inventory covered 322 documentation files and 684 local links,
with no missing local target or section anchor reported. It inventoried 433
remote links without bulk-fetching them. Secret-pattern checks covered 1,543
publishable text files. The single private-key-header match was the existing
truncated secret-detection test fixture, not a usable key. No configured secret
value was found. This screening does not prove the absence of every secret
format, and large binary files were outside the text scan.

The source and clean-wheel suites ran on Python 3.14.4. The clean environment
installed the built wheel with base dependencies, and its dependency check
passed. Runtime-source hashes were unchanged during both suites. Native
Windows and macOS installation was not executed; those guides received
command and policy review only.

The documented one-call model probe now supports explicit
`--allow-unbounded-total-tokens`. The flag does not invent a strict token bound
or imply a zero-cost call. Strict probes still require a qualified exact-request
bound. Offline checks cover conflicting flags and command scope; no provider
integration claim follows from them.

The browser player passed controls, keyboard, scrub, and reduced-motion
checks. Its media identities and stream metadata matched the saved export.
The layout audit checked 26 scenes at two viewport sizes, reporting no text
clipping, horizontal overflow, or console errors. These are browser and media
checks, not a new visual review of every PDF or PowerPoint export. The dated
media remains a snapshot, not documentation of every new feature.
