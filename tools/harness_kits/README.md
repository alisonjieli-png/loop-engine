# Local starter kit previews

Kind: developer tool. Python modules use snake_case names. Serialized kit
records carry their own version; changes to generated bytes change the package
digest. This directory does not own a runtime, registry or publication queue.

The builder creates instructions, skills, optional connection configuration,
feed source profiles and an offline fixture verifier in a fresh directory.
It never installs a harness, calls a model or publishes a library item.

## Use

Run from a Loop Engine source checkout with Python 3.10 or newer:

```bash
PYTHONPATH=src:tools python3 tools/build_harness_starter_kit.py --list
PYTHONPATH=src:tools python3 tools/build_harness_starter_kit.py \
  --kit python-modern-uv-pydantic2 --harness opencode
```

The second command checks a preview without writing it. To write, provide an
existing `--output-root`, a new child `--name` and `--authorize-local-writes`.
Existing files, symlinked roots and unsupported custom overrides are refused.
`--check PATH` reads a kit without executing arbitrary code from that folder.
It requires exact bytes from the current first-party generator and checks feed
profile freshness against today unless an explicit historical date is supplied.
The check applies to a fresh, unchanged kit directory. Unlisted files,
directories and links are refused, including native instruction overrides.
Check before a harness adds its own runtime files; the check does not lock a
directory against changes after validation or validate a merged user project.

The generated README explains native placement and account prerequisites.
Codex and OpenCode optional connections start disabled. Their model account
access is separate from Baltor access. No script that merely prints JSON is
registered as an MCP server. The generated verifier checks demonstration
fixtures and linked feed bytes, not completed customer work.

## Review boundaries

The ten templates and four factory modules came from preserved Antigravity
work based on Loop Engine revision `6787552603b020d7b13ecc7fe6f80c7a83c7aaa0`.
The original private session and source remain preserved outside this repository.
Only selected source files were reconciled; private chats are not kit content.

Existing `CataloguePackage` owns file paths, digests and package identity.
The four `supply_lines/*_factory.py` modules return local preview dictionaries,
not records accepted by `read_supply_candidate`. Their 200 recipe variants
are not 200 independently qualified capabilities, and parameter variations
must not inflate distinct served-component counts. They have no publisher.
Use the existing supply packaging and component qualification path before
admission, including exact source provenance, complete licence evidence,
derived effects, independent behavioral review and near-duplicate checks.

Factory verifiers reject changed bytes and unregistered specifications before
executing trusted first-party templates. They are not arbitrary-code sandboxes.
Execution of modified or outside packages belongs to the existing
`component_qualification.sandbox` boundary. Timing four regex examples is not
a proof of linear complexity. Regex results describe lexical matches, not
semantic validity, checksums, real account identity or standards compliance.
Timezone results depend on the installed IANA timezone database. Calendar
examples do not establish legal deadlines. SQL examples use an in-memory
fixture by default; querying a supplied database requires separate authority.

Drift linters are version-specific heuristics. They may miss aliases and
produce false positives; a clean report is not a security approval. Model
availability and replacements require a current provider check. Credential
findings redact matched values.

## Checks and source decisions

```bash
PYTHONPATH=src:tools python3 -m unittest tools.test_harness_kits_and_factories
```

The guards include changed executable bytes, forged metadata, unsafe roots,
missing feed files and invalid calendar bounds. Native configuration discovery,
generated fixture tests, independent task outcomes and admission remain
different checks.

The placement decision uses the official
[Codex skills guide](https://learn.chatgpt.com/docs/build-skills),
[Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference),
[OpenCode configuration guide](https://opencode.ai/docs/config/) and
[OpenCode skills guide](https://opencode.ai/docs/skills/), checked October 13,
2026. Existing feed-profile compilation, catalogue manifests and the component
sandbox were reused. No separate runtime or publication mechanism was adopted.
