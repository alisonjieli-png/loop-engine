# Mechanism-held-out splits for synthetic task suites

Splits a synthetic task suite by the mechanism that generated each task (a template, a rule family, a simulator setting), so that no mechanism appears in both training and test. It also builds balanced mechanism-level folds and reports leakage in any split you already have.

## When to use it

- A benchmark is generated by a handful of generators and you want to know whether a method transfers to a generator it has not seen.
- You suspect an existing split is optimistic because the same templates are on both sides.
- You need cross-validation folds that keep each mechanism whole.

## Formula

- `split_by_mechanism`: sort the distinct mechanisms, shuffle them with a seeded Fisher-Yates shuffle, and send the first `k = max(1, min(M - 1, floor(fraction * M + 0.5)))` to the test side.
- `group_k_folds`: order mechanisms by task count (largest first, ties by name) and give each to the fold with the fewest tasks so far (ties to the lowest fold).
- `leakage`: the mechanisms present on both sides, the test tasks they affect, and ids that appear on both sides.

## Assumptions and what it does not establish

- Mechanism labels are trusted. Two mechanisms that share hidden structure still leak.
- A mechanism-held-out score measures transfer to these held-out mechanisms. It does not predict transfer to other unseen ones.
- Whole-mechanism test sets are coarser than task-level ones, so the estimate is noisier.

## Parameters

| Name | Meaning |
|---|---|
| `tasks` | `[{id, mechanism}]`, ids unique |
| `holdout_fraction` | share of mechanisms held out, in `(0, 1)` |
| `seed` | non-negative integer |
| `folds` | number of folds, 2 to the number of mechanisms |
| `train_ids`, `test_ids` | an existing split to check |

## Example

```python
from mechanism_heldout_split import leakage, split_by_mechanism

tasks = [{"id": "t1", "mechanism": "m1"}, {"id": "t2", "mechanism": "m1"}, {"id": "t3", "mechanism": "m2"},
         {"id": "t4", "mechanism": "m3"}, {"id": "t5", "mechanism": "m3"}, {"id": "t6", "mechanism": "m3"}]
leakage(tasks, ["t1", "t3", "t4"], ["t2", "t5", "t6"])["leaked_mechanisms"]   # ["m1", "m3"]
split_by_mechanism(tasks, 0.34, seed=0)["test_ids"]                             # ["t1", "t2"]
```

Command line:

```bash
echo '{"call": "group_k_folds", "arguments": {"tasks": [{"id": "a", "mechanism": "x"}, {"id": "b", "mechanism": "y"}], "folds": 2}}' | python3 mechanism_heldout_split.py
```

## Limits

- Greedy balancing is approximate.
- Labels may be text or integers; booleans are refused.

## Files

- `mechanism_heldout_split.py`: the functions and the JSON command line.
- `numerics.py`, `atom_cli.py`, `schema_lite.py`: shared helpers.
- `test_mechanism_heldout_split.py`, `test_package.py`: run with `python3 -m unittest`.
