# Development-tool instructions

Follow [the repository rules](../AGENTS.md) and read the advisory comments in
[ASTRA.md](../ASTRA.md). For harness work, also read
[the harness development instructions](../embodiments/AGENTS.md).

An outer Loop Engine Loop can supervise native harness iteration. Treat
wrapper composition and control ownership as explicit experiment dimensions,
not a fixed stack or a single all-on/all-off setting. Preserve independent
task acceptance, cumulative authority, cancellation, and exact output identity.

Design comparisons that can add cognitive steps, actions, prompts, questions,
intelligence, and verification as well as simplify a procedure. Freeze each
experiment's population and treatments without closing the product's design
space. Record failed and excluded attempts alongside successful ones.

Reuse the canonical Loop and existing registries for governed product work.
Keep the dependency direction from development tools into the product;
production code must not import this directory. Preserve the separate,
standalone qualification laboratory and effect-free bootstrap checks.

Use owned test processes and new scoped output locations. Preserve concurrent
changes and immutable reports. Do not change provider configuration, native
control flags, historical artifacts, or failure baselines to make a
documentation check pass.

Read [README.md](README.md), the
[layered harness design](../docs/architecture/LAYERED-HARNESS-WRAPPERS-AND-NATIVE-CONTROL.md),
and the [configuration search guide](../docs/guides/configuration-grid-search-and-optimization.md)
for the relevant boundaries and verification requirements.
