# Cross-project remixes

Each folder states one integration invariant, its source lineages, a smallest-change plan and independent qualification gates. These are planned integrations. They do not claim that a source archive has become a working Loop Engine capability.

| Remix | Main question |
|---|---|
| [repair_with_governed_reuse](repair_with_governed_reuse/) | Can the practical repair workflow reuse independently qualified code safely? |
| [hybrid_gateway_and_tools](hybrid_gateway_and_tools/) | When does tool agency justify a harness call? |
| [local_product_with_durable_solver](local_product_with_durable_solver/) | Can local execution support durable work and continuously available results? |
| [horizons_with_scoped_pull](horizons_with_scoped_pull/) | When does scoped pull improve a bounded pushed packet? |

No remix owns another runtime, event log or promotion store. Keep one authority for each concept and name any intentional experimental change in the manifest before comparing it.
