# Original native generation tooling, September 23, 2026

This directory records a candidate generator and a frozen ten-method plan.
No live model/provider call has been made by this implementation task, and no
real generated package is counted here. Unit tests use explicit injected
gateway fixtures and retain the fixture marker.

Initial scoped verification: 48 tests passed across generation, the native factory
and provider identity. The generation module contains 21 tests. Seven
removed-guard controls detect missing plan binding, physical-call ceiling,
model identity, strict token-bound source, resume binding, complete file
inventory and package deduplication. Ruff and Markdown lint pass; repository
documentation link checks report no broken targets. This is local contract
evidence, not live model quality or full release qualification.

## Successor after independent review

Independent review reproduced mutable prepared metadata, lost error-body usage
and an omitted physical-attempt identity. The source fixes now bind the entire
prepared tree (including specifications, reports, effects and producer
declarations), retain observed usage on provider error bodies, and record the
actual final physical-attempt identity separately from the top-level gateway
result. The run and journal contracts are version two; historical version-one
runs cannot resume through automatic reinterpretation.

The known-wrong checks are retained in
`independent-findings-before-repair.txt`. A further regression demonstrated
that a persistent model-identity failure continued to other methods; the
generator now stops that campaign immediately. Its failure is retained in
`model-identity-stop-before.txt`.

The first successor passed 53 tests, including 25 generation tests, with nine
generator removed-guard controls detected. No real provider calls or new
admission decisions were made. The final independent rereview remains a
separate integrating-session gate.

A final review also required direct gateway/provider implementation digests
on resume and unknown answering identity on every unanswered provider branch.
The run binding is now version three; the completion journal remains version
two. Missing-key, invalid-capacity, transport, malformed-response and adapter
exception results retain unknown actual identity; preflight refusals report
zero physical requests. Requested identity remains separate. The final set
passes 57 tests, including 26 generation tests and seven provider tests.

Read the [operator guide](../../tools/GENERATE-ORIGINAL-NATIVE-CANDIDATES.md)
for the fixed contracts, call-limited and strict-token modes, safe resume,
failure records and admission boundary. The task authority remains the existing
roadmap; this artifact is not another task list.

## Preserved failures

- `tests-first.txt`: the first generator suite found that timeout changes
  were not bound on resume. The run record now binds the timeout.
- `seed-plan-invalid-tag-1.json`: the initial authored plan used a tagging
  dimension the repository does not support. The current `seed-plan.json`
  uses existing dimensions and keeps Python in search metadata.
- An intermediate owning-check command named a nonexistent test module,
  `tools.test_native_harness_candidates`. The correct factory module is
  `tools.test_prepare_native_harness_candidates`. That was a verification
  command error, not a product failure.

The ten planned methods contain seven intended text files each. Those 70 paths
are requested outputs, not created or approved intelligence. Exact package
duplicates are refused; semantic duplication, model quality, execution safety,
rights and native use need independent review.

## Dependencies and scope

The generation delta depends on the frozen native-factory patch
`f705e8dbbd625e42a196f5dea360867188b1453ab2d6ab7a4828ce10f62e5417`.
Its v2 proposals produce complete v3 candidate items and specifications.

The separate provider-identity prerequisite removes missing-model fallbacks
from Ollama and the gateway. It preserves requested identity in the route and
attempt's expected-model field, refuses unreported or mismatched answering
identity and retains usage. It is independently exported for integration.
