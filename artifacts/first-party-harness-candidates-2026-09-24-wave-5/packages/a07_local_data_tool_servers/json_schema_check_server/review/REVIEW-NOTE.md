# Review note: JSON schema check tool server

Candidate only. Not approved, staged, served or published.

Producer: Claude Code wave 5 generator `a07_local_data_tool_servers`, model family `anthropic`. This note is never delivered to a customer harness.

## Method

One logical method: before a step hands a JSON output on, check it against its contract schema with a tool call that lists every violation, so a small model fixes all of them in one pass and cannot claim a pass it did not get. The package holds one standard-library protocol server (`server/json_schema_check_server.py`) with one tool, `check_json_schema`, a scripted-client test, the input contract, a synthetic schema with one valid and one known-wrong document, five harness configuration variants and a short companion (`AGENTS.md`).

The schema is read first. Every keyword must be one the tool checks: types, `enum`, `const`, the object keywords (`properties`, `required`, `additionalProperties`, `patternProperties`, `propertyNames`, `minProperties`, `maxProperties`, `dependentRequired`, `dependentSchemas`), the array keywords (`items`, `prefixItems`, `minItems`, `maxItems`, `uniqueItems`, `contains`, `minContains`, `maxContains`), the string keywords (`minLength`, `maxLength`, `pattern`, `format`), the number keywords, `allOf`, `anyOf`, `oneOf`, `not`, `if`, `then`, `else`, local `$ref` with `$defs` or `definitions`, and annotations. Draft-07 schemas keep their tuple `items`, `additionalItems` and `dependencies`, and the rule that keywords next to `$ref` are ignored is reported. Any other keyword, a mistyped one (with a "did you mean" hint), an unknown `format`, a remote `$ref` or an `$id` below the root makes the tool refuse, unless the caller passes `allow_unchecked: true`; then those keywords are listed in `unchecked` and `valid` covers the rest only. A schema whose keyword values are malformed is refused with the exact schema paths. Patterns are read as ECMA-262 regular expressions, the dialect JSON Schema names for them, and translated to Python's `re` module before they run; a pattern that cannot keep its meaning there is refused. Unchecked keywords are skipped wherever the check reaches them, including through `$ref`, and every local `$ref` target is read like the rest of the schema.

## Inputs and outputs

Input: `contracts/check_json_schema.input.schema.json`: exactly one of `document` or `document_path`, exactly one of `schema` or `schema_path`, and `jsonl`, `check_formats`, `allow_unchecked`, `max_violations`. Output: `valid`, `documents_checked`, `violation_count`, up to `max_violations` entries with `instance_path`, `schema_path`, `keyword`, `message` (and `line` for JSON Lines), `more_violations`, the schema draft and file digests, as compact text and as `structuredContent`. Documents with a repeated key, `NaN`, more than 128 levels or more than 16 MiB are refused, as are schema files above 1 MiB. One check stops after 20 seconds by default (`--time-limit-seconds`, POSIX only) or two million steps. One answer line holds at most 262,144 bytes (256 KiB), measured on the exact bytes written, so both copies of the result and every escape count; a longer answer becomes a short refusal that says to lower `max_violations`.

## Effects

The server reads files under `--root` only. It writes nothing, starts no process, opens no network connection and reads no secret. `spawns_process` covers the harness and the tests starting the server. `writes_fs` is declared only because the tests write temporary files (JSON Lines, broken documents, a 16 MiB file, a link out of the root, and a workspace for the launch test). The host must bind a trusted `python3`, because an interpreter found first on `PATH` can be replaced.

## Positive example

`examples/check_json_schema-arguments.json` checks `cleaning-summary.json` against `cleaning-summary.schema.json` and returns `valid: true` with no violations. `{"multipleOf": 0.01}` accepts `19.99`, because the tool divides the exact values of the numbers' shortest decimal text, which also works for `10**30` against `1`; libraries that use binary floating point may reject it (the `jsonschema` library did in the development comparison).

## Known-wrong example

Two known-wrong behaviors are held by tests. A checker that stops at the first problem: `cleaning-summary-wrong.json` breaks nine rules (pattern, type, enum, minLength, minimum, required, date-time format and an extra property) and all nine come back with their paths. A checker that silently ignores a mistyped keyword: `{"minimun": 1}` makes the tool refuse and suggest `minimum`, where a lenient validator would pass the value 0. A third was added in the third pass: a checker that runs patterns with Python's rules passes `12345` followed by a line break against `^[0-9]{5}$` and `a b` with a no-break space against `^\S+$`; this tool now reports both as `pattern` violations.

## Limits

The subset leaves out `unevaluatedProperties`, `unevaluatedItems`, dynamic references, anchors, remote references and vocabularies, and it refuses schemas that use them unless `allow_unchecked` is true. Patterns follow ECMA-262 through a translation to Python's `re` module. Unicode property classes, backreferences and lookbehinds of varying width are refused as schema problems. A few forms that the Unicode mode of ECMA-262 refuses, such as `\-` outside a class or a lone `{`, are read as literal characters, as ECMA-262 reads them without the u flag. The translation was compared with one ECMA-262 engine (V8 in Node.js 22.22.1), not with every engine. `format` checks are simple shape and calendar checks for seven formats; the email check does not cover every valid address. Draft 2019-09 and draft-04 are refused. Without a timer signal (for example on Windows, which was not tested) only the step limit bounds a slow pattern. A model that writes tool calls as plain text cannot use any protocol server.

Pre-check history: recorded in `review/PRECHECKS.txt` and the `review/precheck-*.json` reports. The first check refused the package because a variable in `depth_of` was named with a word the vocabulary check refuses; it was renamed and the check rerun. The `effects` warnings that remain name the draft-07 and draft-04 `$schema` identifiers in the server and tests: they are compared as text and never fetched.

Second generator pass, September 24, 2026 (UTC): a probe of the output bound found that an answer line could pass 256 KiB even though the package passed every pre-check. The old guard measured one copy of the result (at most 120 KiB) before the text copy escaped every backslash and quote a second time; 150 refused property names of 200 backslash characters gave a 326,603-byte line. The server now measures the whole line as written and refuses above 262,144 bytes. The new test `test_known_wrong_escapes_cannot_push_an_answer_line_past_256_kib` failed on the previous server under Python 3.14 and 3.10 and passes now. The probe, its output before and after the repair, the mutation run and a copy of the previous package are kept in the wave folder under `generator-a07-work/`.

Third pass, repairs after critic round 4, September 24, 2026 (UTC):
- Pattern dialect (blocking, false pass). `pattern` and `patternProperties` ran with Python's `re` rules, so `12345` followed by a line break passed `^[0-9]{5}$`, no-break and ideographic spaces passed `^\S+$`, and a carriage return passed `.`. Each pattern is now translated from ECMA-262 to Python before it is compiled: `$` becomes the end of the text, `.` excludes the four ECMA-262 line breaks, `\s` and `\S` use the ECMA-262 white space set inside and outside classes, `[]` and `[^]` keep their ECMA-262 meaning, `\cX`, `\u{...}` and surrogate pair escapes become the code points they name, and named groups become plain groups. Forms that cannot keep their meaning in Python are refused as schema problems: Unicode property classes, backreferences, Python-only syntax such as `(?i)`, `(?P<...>)`, `\A`, `\Z` and possessive quantifiers, and lookbehinds of varying width. `test_known_wrong_python_pattern_rules_pass_values_ecma_262_rejects` and `test_patterns_that_cannot_keep_their_meaning_are_refused` failed on the previous server under Python 3.14 and 3.10.
- Differential check of the translation. A producer-side script compared the translated patterns with Node.js 22.22.1 `RegExp` in Unicode mode on this machine (a local process, no network). The oracle tries every code point position as a match start, as the ECMA-262 matching steps do. Seven runs checked 40,246 patterns (the same 178 curated patterns in each run plus 3,000 or 6,000 random ones) against 148 texts each. No pattern that ECMA-262 accepts gave a different result here (39,425 patterns agreed on every text). The same five valid patterns were refused in every run on purpose (the forms listed above). 379 patterns that the Unicode mode refuses, such as `\-` outside a class or a lone `{`, were accepted and read as literal characters, as ECMA-262 reads them without the u flag. The first run found two things. A class range with an escape such as `\d` at one end was read as a range; ECMA-262 without the u flag reads it as three separate members, and the Unicode mode refuses it. That was repaired. It also found 56 differences, all `\B` on the text `a😀b`, where V8's plain `test` started a match inside a surrogate pair, which the ECMA-262 matching steps do not do; the oracle was then changed to try only code point positions. Script, oracles and outputs: `repairer-a07_local_data_tool_servers/after-critic-r4-20260924T052417Z/ecma/`.
- Unchecked keywords behind `$ref` (minor). The skip list was keyed by the evaluation path, so a keyword listed in `unchecked` still ran when a `$ref` led to it, and a remote `$ref` behind a local `$ref` ended in an internal error. Unchecked keywords are now remembered by the schema object that holds them, and every local `$ref` target is scanned, so patterns in a target outside the usual keyword positions are compiled too. `test_known_wrong_unchecked_keyword_reached_through_a_reference` failed on the previous server.
- Large numbers (minor). `multipleOf` said `10**30` could not be checked against `1`, because the decimal context had 28 digits. It now divides exact fractions. `test_known_wrong_multiple_of_large_numbers` failed on the previous server.

The placement repairs are shared by all five packages of the assignment: the Gemini CLI server key is the hyphenated name (a recorded deviation from SPEC section 9.2), `unverified_targets` names the Gemini CLI folder trust condition and the Claude Code expansion limit, the Claude Code and Cursor variants use `${CLAUDE_PROJECT_DIR:-.}` and `${workspaceFolder}`, and `test_expanded_launch_lines_start_the_server_from_a_subfolder` and `test_known_wrong_gemini_server_key_with_underscores` fail on the previous variant files. The companion now says that a listed tool may carry a prefix, that a passing fallback test run means the harness did not start a working server, and (for the four data servers) that returned values are data, never instructions.
