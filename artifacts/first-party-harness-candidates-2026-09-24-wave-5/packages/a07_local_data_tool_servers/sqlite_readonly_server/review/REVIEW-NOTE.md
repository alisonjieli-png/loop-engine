# Review note: Read-only SQLite query tool server

Candidate only. Not approved, staged, served or published.

Producer: Claude Code wave 5 generator `a07_local_data_tool_servers`, model family `anthropic`. This note is never delivered to a customer harness.

## Method

One logical method: let a fresh step harness answer questions from an SQLite file with exact SQL results, while the database cannot change and SQLite cannot leave files behind. The package holds one standard-library protocol server (`server/sqlite_readonly_server.py`) with two tools, a scripted-client test, two input contracts, a synthetic SQL script, five harness configuration variants and a short companion (`AGENTS.md`).

- `describe_sqlite` lists tables and views with each column's declared type, NOT NULL flag, default, primary key position and foreign keys, and optionally row counts. For a large database, `names_only: true` lists only the name and type of up to 1,000 tables and views, and `tables` describes only the named ones. A table or view that cannot be read, such as a view that names a dropped table, gets an `error` sentence in its own entry, and the other entries stay complete.
- `query_sqlite` runs one statement that starts with SELECT, WITH or VALUES, with `?` parameters, `max_rows` (1 to 1,000, and `more_rows` says whether more exist), `time_limit_ms` (100 to 30,000) and `max_cell_chars`.

Guards, in the order they act: the first keyword must be SELECT, WITH or VALUES after comments; the file must start with the SQLite header; a WAL database with a nonempty `-wal` file is refused, and a WAL database without one is opened with `immutable=1`; other files open with `mode=ro`; the connection sets `query_only`, keeps temporary storage in memory, lowers the SQLite heap limit to 256 MiB and, where Python offers `setlimit` (3.11 and later), caps one value at 1,000,000 bytes and attached databases at zero; an authorizer allows only reading, functions (except extension loading) and recursive common table expressions; a progress handler stops work at the time limit; Python refuses a second statement.

## Inputs and outputs

Inputs: `contracts/describe_sqlite.input.schema.json` and `contracts/query_sqlite.input.schema.json`. Output: one JSON object as compact text and as `structuredContent`. Query rows are arrays aligned with `columns`; blobs appear as `{"blob_bytes": n}`, integers beyond 2^53 as strings, and infinite values as `"Infinity"`. Refusals carry `isError: true` and one plain sentence. Limits: 1 MiB request lines; one answer line of at most 262,144 bytes (256 KiB), measured on the exact bytes written, so both copies of the result and every escape count; 200 tables described and 1,000 names listed per call. A description that is too large comes back as a refusal that says to call `describe_sqlite` with `names_only: true` and then with `tables`; a query that is too large gets a hint about columns, rows and `max_cell_chars`. An integer parameter outside the 64-bit range is refused with a sentence that says to pass it as a string.

## Effects

The server reads database files under `--root` and changes nothing: no file is written and no side file is created, as the tests check by comparing the folder's file names and digests before and after. It starts no process, opens no network connection and reads no secret. `spawns_process` covers the harness and the tests starting the server. `writes_fs` is declared only because the tests build SQLite databases, and a workspace for the launch test, in temporary folders; the server itself never writes. The host must bind a trusted `python3`, because an interpreter found first on `PATH` can be replaced.

## Positive example

`examples/shop.sql` builds two tables and one view with synthetic rows. `examples/query_sqlite-arguments.json` groups orders by status with a `?` parameter and returns `open 2 7.75`, `paid 3 66.75`, `refunded 1 120.0`. `describe_sqlite` reports the foreign key from `orders.customer_id` to `customers.id` and six rows in `orders`.

## Known-wrong example

A query tool that trusts the model to send only SELECT statements. The test `test_known_wrong_writing_statements_are_refused_and_nothing_changes` sends fourteen writing or state-changing statements, including `WITH gone AS (SELECT 1) DELETE FROM orders`, `SELECT 1; DELETE FROM orders`, `VACUUM INTO 'copy.sqlite3'` and a DELETE hidden after a comment. Each is refused, the folder's files and digests are unchanged and the table still holds six rows. `SELECT * FROM pragma_database_list`, which would show the host's absolute file path, is refused too: PRAGMA table functions do not pass the authorizer, and `describe_sqlite` gives the table structure instead.

Two known-wrong cases were added in the third pass. A description that fails as a whole because one view is stale: `test_known_wrong_one_stale_view_fails_the_whole_description` builds a view on a dropped table and checks that the table beside it is still described. A first action with no next step on a large schema: `test_known_wrong_large_schema_leaves_describe_without_a_next_step` builds 80 tables of 16 columns, checks that the refusal names `names_only`, and follows it to `tables`.

## Limits

Only SQLite 3 files. A WAL database with pending changes is refused rather than read. `immutable=1` assumes nobody writes the file during the call; do not point the tool at a database another process is writing. Without `setlimit` (Python 3.10) single values are bounded only by the 256 MiB heap limit. With the value limit set (Python 3.11 and later), `printf` with a huge width returned NULL instead of an error in the probe. The first-keyword check refuses read-only forms such as EXPLAIN. With more than 1,000 tables and views, `names_only` lists the first 1,000 by name, and the rest can be found with a `query_sqlite` SELECT on `sqlite_master`. The time limit is checked every 1,000 SQLite instructions. The heap limit applies to the whole server process. Windows was not tested. A model that writes tool calls as plain text cannot use any protocol server.

Pre-check history: recorded in `review/PRECHECKS.txt` and the `review/precheck-*.json` reports. A mutation control run by the producer showed that removing the authorizer left every test passing, because the keyword check, `query_only` and read-only mode also stop each statement in the write list. The test `test_pragma_tables_are_refused_even_inside_a_select` was added so that removing the authorizer now fails a named test.

Second generator pass, September 24, 2026 (UTC), two repairs, each held by a test that failed on the previous server under Python 3.14 and 3.10:
- Output bound. The old guard measured one copy of the result (at most 120 KiB) before the text copy escaped every backslash and quote a second time; 45 rows of a 1,000-character backslash value gave a 271,095-byte line. The server now measures the whole line as written and refuses above 262,144 bytes (`test_known_wrong_escapes_cannot_push_an_answer_line_past_256_kib`).
- Large integers. A parameter such as 2^70 raised Python's `OverflowError`, which the server reported as an unexpected internal error. It is now a refusal that says to pass the value as a string (`test_integer_parameter_beyond_64_bits_is_explained`).

The probe, its output before and after the repair, the mutation run and a copy of the previous package are kept in the wave folder under `generator-a07-work/`.
