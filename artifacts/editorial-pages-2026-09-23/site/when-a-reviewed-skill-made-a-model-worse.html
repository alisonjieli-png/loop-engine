Experiments

When a reviewed skill made a model worse

Our first data cleanup study found a phone-number instruction that reduced accuracy. The result changes what we need to check before recommending material.

Baltor · September 23, 2026 · 3 minute read

A reviewed instruction can still make a task harder. In our first data cleanup study, a cheap cloud model handled phone numbers more accurately without the selected Baltor instruction than with it. We kept the failed runs and changed the homepage example. The result belongs in the product's evidence, alongside the parts that worked.

What we tested

The study used 143 synthetic rows across phone numbers, email addresses, postal addresses and duplicate company records. The phone set contained 38 records. These were constructed test cases, including numbers reserved for fiction, rather than customer data.

Source: Full data cleanup report and limitations

Each assignment started a fresh Pi 0.73.1 process. We ran each model and material condition three times per task family. The complete campaign used 72 counted steps and 225 physical model requests within a 400-request ceiling. This was a harness-and-material study, not a full-system benchmark of the complete Baltor design.

The study author constructed this synthetic population and knew the catalogue items. Its challenging cases follow real conventions, and their frequency affects the size of the difference. This is not an estimate of error rates on customer data.

Source: Frozen design and claim rules

The phone result

With glm-5.3-flash:cloud, phone-record accuracy averaged 99.1 percent without the selected instruction and 84.2 percent with it. The three runs without the instruction passed the task check; none of the three with it passed. The task check required at least 90 percent accuracy and no wrong change to an already correct value.

The instruction relied on a digit-count method that did not handle several cases in this population. It mishandled a United Kingdom trunk-prefix notation, an international dialling prefix and numbers whose apparent length did not make them valid. The model followed that incomplete method instead of applying knowledge that had produced better results without it.

Two failures with different causes

The local qwen2.5-coder:7b model failed earlier in the workflow. It wrote tool requests as plain text, so this version of the harness ended the step without an output file. That is evidence about this model-and-harness connection. It does not establish that local models cannot perform data cleanup.

For the cloud model, more instructions also meant more work. The study recorded more prompt tokens, requests and elapsed time with the material in every family. No task family showed a clear improvement under the study's predeclared comparison rule. Those results do not measure every model, task or possible instruction.

What needs to change

The phone item has been removed from the homepage demonstration. Its catalogue disposition is a separate review decision. A replacement needs tests for the exact failed cases, an explicit scope, and a new comparison using the same task and model conditions. Rewording the item or changing its recorded source revision would not by itself repair the method.

For future recommendations, we need to check that the client can operate its tools, that the selected material reaches the model, and that the resulting work passes an independent task check. A successful download proves receipt of bytes. Tool operation, model use and task acceptance each need their own evidence.

Draft review gate

Before publication, record the affected catalogue item's current disposition and obtain an independent factual review of this article.
