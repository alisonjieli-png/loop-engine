What your harness actually reads

A skill can contain instructions, scripts and reference files. Its location and loading rules determine what reaches your agent.

Baltor · September 23, 2026 · 2 minute read

Putting a file in a project directory does not tell you whether an agent read it. Your harness decides which instruction files it loads, where it looks for skills and when it starts a tool. Those rules are part of the connection you need to test.

One skill may contain several files

The Agent Skills format uses a directory with a SKILL.md entry file. That file carries a name and description, followed by instructions. A skill can also include scripts, references and assets. A data-checking skill might pair its instructions with a Python validator and an input schema.

Source: Agent Skills specification

audit-a-data-file/
  SKILL.md
  scripts/check_rows.py
  references/input-schema.json

This is one logical package with three files. The package needs all the files its procedure uses, and each file needs a stable identity. Reviewing the instruction page alone does not establish what the Python code does.

Discovery, loading and use are different

The Agent Skills specification describes loading in stages. A harness can discover a skill's name and description before loading the instructions. It can then read a script or reference when the task needs it. This lets a library hold more material than belongs in one model request.

Source: Agent Skills specification

An installation check should first confirm that the client discovers the selected item. A later observation should show that the content or tool enters the step, and another should show how the agent uses it. The output still needs its own acceptance check. A file can pass the first checks and remain irrelevant to the task.

Use the client's native paths

Different clients have different instruction names, skill directories and trust settings. Some also load material from a home directory or a parent project. A newly created working directory can therefore inherit instructions you did not place there.

For a focused step, start with a named client version, a clear assignment and a recorded set of selected files. Check inherited configuration as well as the new folder. Use the client's documented setup, and test that setup before relying on a filename as evidence of loading.

A file does not grant permission

A script may read data. A configuration may start a process or contact a server. The customer's tool settings and explicit permissions govern those actions. A useful package should explain its inputs, dependencies and effects, so the customer can decide whether it fits the step.
