## Findings and repairs

### 1. Floating-point decoding created invalid integer authority

The first root context selector accepted `1.00000000000000001` as integer one
and `1e-9999` as zero. The latter could admit a required block at an incorrectly
zero declared cost. The [raw reproducer](root-wire-counterexamples-1.json) and
[failed 52-case report](root-independent-adversarial-1.json) preserve the exact
source and observations.

The author replaced binary-float parsing with bounded exact integer parsing.
The [first successful successor](root-independent-successor-2.json) also checks
huge nonzero exponents without allowing unbounded integer expansion.

### 2. Decimal's exponent range was narrower than the declared zero input

The data author identified a valid-input refusal for a zero coefficient with
an exponent outside Decimal's representational range. QA independently
[reproduced it in the root selector](root-zero-exponent-counterexample-1.json).
A zero coefficient remains zero regardless of exponent size.

Both authors normalized zero mantissas before Decimal conversion. The final
root report and four independent data-method controls accept this input while
retaining the nonintegral and nonzero overflow/underflow refusals. The authors'
old scripts and failed observations remain in the surrounding verification
artifacts; this review did not edit authored payloads.

### 3. CSV header precondition needed to be explicit

The CSV implementation correctly required an actual nonempty first parsed CSV
record when `header=true`, but its initial prose did not state that prerequisite.
The author clarified the input schema description, instructions and metadata.
The final CSV replay covers both an empty document and an empty parsed first
record. A present field whose header name is empty remains a different case.
No behavior was weakened.

### Test-suite improvement

An independent deliberately wrong Kahn implementation showed that the initial
`a,b,c` example did not distinguish draining a ready batch from selecting one
smallest ready node at a time. The added `a,b,z` case does distinguish them.
A second independent wrong algorithm counts ties as sign-test trials and returns
5/8 where the declared exact result is 1. Both wrong methods complete normally
and are detected by the [independent control report](wrong-algorithm-controls-1.json).

The systems author also strengthened its packaged fixture set after its own
plain-prefix-as-ancestry mutant escaped. This QA's existing `a` versus `ab/y`
case already distinguished that mistake. The final systems report binds the
strengthened fixture file; its algorithm bytes did not change.

## Isolation and exact-byte binding

Execution reused the existing trusted
`loop_engine.core.library_ingestion.processes.run_command` owner from source
revision `231f51bb1facab517fbe915b08ea9ac85f913347`. No new application runtime,
catalogue, engine registry or admission mechanism was created.

Candidate implementations were never imported or executed on the host. Frozen
script bytes and synthetic inputs were bound read-only into a minimal Bubblewrap
namespace. The host home was absent; environment variables were cleared;
network, process and other namespaces were unshared; capabilities were dropped.
The sandbox had only the system interpreter/libraries, the script, input,
trusted runner, temporary storage and two explicitly bound output files.

Limits were two CPU seconds, 256 MiB address space, four seconds wall time,
32 descriptors, one permitted process and no core dumps. File-size limits bound
stdout/stderr before capture, avoiding reliance solely on post-capture truncation.
The small root/systems fixture runs used 65,536 bytes per stream; data runs used
524,289 to observe their declared 524,288-byte output boundary. These fixture
runs do not qualify every maximum-volume input or output shape.

Separate controls verified an absent home directory, stopped an infinite loop,
refused an oversized allocation and capped a one-megabyte write at 65,536 bytes.
See [initial sandbox smoke](sandbox-smoke-1.json),
[output-bound control](sandbox-output-bound-1.json) and
[CPU/memory controls](sandbox-resource-controls-1.json).

Every execution report records exact script/input digests, complete package
file bindings, output digest, exit status, schema result, elapsed time and
resource observations. It compares the authored tree before and after the run.
The final summary then checks all current trees against the selected successful
reports. Source changes require new evidence; old records are not rewritten.

## Source, effect and usefulness review

Source inspection found standard-library methods over supplied data. No method
opens task files, performs network/credential lookup, launches a subprocess or
writes persistent state. The host still needs authority to launch Python and
load its code. Root/data metadata declare `reads_fs` and `spawns_process` for
that launch; systems metadata separately declares the interpreter launch while
its instructions disclaim task-file access. These labels grant no authority.

The instructions accurately bound the useful methods:

- Context rendering returns text/state; file placement and native discovery are
  separate. Quoting is a trust cue, not a prompt-injection security guarantee.
- Capability evaluation operates on supplied observations; it does not authenticate
  them, negotiate a protocol or approve an engine.
- Context selection preserves required dependency closure and greedily admits
  optional blocks using supplied costs; it makes no token-fit or optimal-knapsack claim.
- Paired sign testing states its null/independence limits and distinguishes ties,
  missing values and effect direction.
- File inventory comparison trusts supplied metadata. Closure reports cycles and
  does not choose versions or establish an install order. Digest sharding is fixed
  modulo, not consistent hashing or a balance guarantee.
- Event precedence checks the supplied sequence, not real-world causality. Text
  edits use original codepoint offsets. The path tool states its exact Unicode
  comparison model and disclaims filesystem/security emulation.
- The CSV package extends an earlier audit with a dialect, width distribution and
  baseline-column completeness. Keyed reconciliation adds actual typed pairing
  and field differences rather than renaming the earlier join-cardinality audit.
  These overlaps and new operations are disclosed; no claim of sixteen novel
  algorithms is made.

The package interfaces differ. Each consumer must use the selected package's
own schema and refusal contract; a common `.py` extension is not an interface
or permission protocol.
