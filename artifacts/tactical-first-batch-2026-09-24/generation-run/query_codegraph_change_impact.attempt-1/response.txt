To find what is *affected* by a change, we must traverse the graph in reverse: `dependency -> consumer`.\n2. **BFS Traversal**: \n   - Start a queue with all `changed_symbol_ids` at distance 0.\n   - For each node, visit all its neighbors in the inverted graph.\n   - Use a `visited` map to store the shortest distance and the path taken to reach the node.\n3. **Termination Conditions**:\n   - **Cycle**: The `visited` check ensures cycles do not cause infinite loops.\n   - **Depth Limit**: If `current_distance == max_depth`, stop exploring that branch and set `is_truncated = true`.\n   - **Node Limit**: If `len(visited) == max_nodes`, stop and set `is_truncated = true`.\n\n## Complexity\n- **Time**: $O(V + E)$ where $V$ is symbols and $E$ is edges.\n- **Space**: $O(V)$ to store the adjacency list and visited map.\n\n## Known-Wrong Approach\n- Using DFS: DFS does not guarantee the shortest path/distance in an unweighted graph.\n- Using a simple recursive visitor without a depth limit: Can cause `RecursionError` on deep chains.\n- Assuming all symbols in the graph are part of the impact: Must only report nodes reachable from the changed set."
