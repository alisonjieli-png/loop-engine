Validate that `budget` and `cost` are strictly integers (not booleans).\n2. **Graph Construction**: Map each section to its `predecessors`.\n3. **Mandatory Closure**: Identify all sections marked `mandatory=true`. Recursively find all their predecessors. This set is the 'Mandatory Closure'.\n4. **Validation**: \n   - If any predecessor in the closure is missing from the input, refuse with `MISSING_DEPENDENCY`.\n   - If the mandatory closure contains a cycle, refuse with `CYCLIC_CONSTRAINT`.\n   - If the sum of costs in the mandatory closure > `budget`, refuse with `BUDGET_EXCEEDED_MANDATORY`.\n5. **Greedy Expansion**: \n   - Sort all non-mandatory sections by `priority` (descending) and then by original input index (ascending).\n   - For each section, calculate the cost of its own 'closure' (itself + all unselected predecessors).\n   - If `current_cost + closure_cost <= budget`, add the entire closure to the selected set.\n6. **Topological Sort**: Order the selected sections such that for any section $S$, all its predecessors appear before it. Use a stable DFS to maintain input order where possible.\n7. **Byte Offsets**: Concatenate the `text` of selected sections and record the start/end byte offsets in UTF-8.\n\n## Complexity\n- Time: $O(N \cdot (N+E))$ where $N$ is number of sections and $E$ is number of constraints.\n- Space: $O(N+E)$ to store the graph.\n\n## Limitations\n- Does not attempt to optimize the knapsack problem; uses a greedy priority-based approach.\n- Assumes `text` is valid UTF-8."
