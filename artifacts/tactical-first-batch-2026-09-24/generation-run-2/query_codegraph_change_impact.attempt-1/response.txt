      "content": "# Algorithm: Reverse BFS for Change Impact\n\n## Logic\n1. **Graph Inversion**: The input provides edges as `consumer -> dependency`. To find what is affected by a change in a dependency, we must traverse the graph in reverse: `dependency -> consumer`.\n2. **BFS Traversal**: \n   - Start a queue with all `changed_symbol_ids`.\n   - For each node, visit all its neighbors in the inverted graph.\n   - Track `distance` (number of hops) and `witness_path` (the sequence of IDs).\n3. **Tie-breaking**: If multiple paths reach a node at the same shortest distance, the path that is lexicographically smaller is chosen to ensure determinism.\n4. **Termination & Bounds**:\n   - **Depth Limit**: If a node's distance equals `depth_limit`, its neighbors are not explored. `metadata.incomplete` is set to `true`.\n   - **Node Limit**: If the number of impacted consumers reaches `node_limit`, traversal stops. `metadata.incomplete` is set to `true`.\n   - **Cycles**: Standard BFS `visited` set handles cycles naturally.\n\n## Complexity\n- **Time**: $O(V + E)$ where $V$ is symbols and $E$ is edges.\n- **Space**: $O(V)$ to store the adjacency list and visited map.\n\n## Known-Wrong Approach\n- Using DFS: DFS does not guarantee the shortest path/distance.\n- Using a simple set for visited without distance: Fails to update a node if a shorter path is found later.\n- Ignoring the `depth_limit` in the `incomplete` flag: Leads to false claims of complete impact coverage."
