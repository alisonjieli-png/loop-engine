# Candidate review: audit a model-specific skill rendering

Status: candidate only. No independent approval, publication, native-load test, or measured benefit.

- Original basis: first-party semantic-retention method from the repository's model-conditioned intelligence research. It does not copy a third-party skill or claim a model-specific optimum.
- Facets: intelligence editor, harness engineer, or independent reviewer; multi-model agent service; derivative candidate review stage; exact model revision and client layout matter.
- Search phrasings: "Did the shorter version of this skill drop an important rule?"; "Can we use this simplified instruction with the small model without changing its permissions?"
- Typed input/output concept: `ApprovedSourcePackage`, `DerivativeCandidate`, `TransformationRecord`, `ModelIdentity`, and `NativeLayout` to `ObligationMatrix`, `FormatFinding[]`, and `TestProposal[]`.
- Effects: read-only audit. No rewrite, approval, install, publication, or model experiment.
- Positive fixture: a source skill has required output fields, a no-network rule, and a stop condition; a shorter candidate preserves all three with traceable passages and matching relative references. Return no detected semantic loss while still requiring independent approval and task evaluation.
- Known-wrong fixture: the candidate drops the no-network rule and changes "hold when approval is missing" to "proceed when approval is missing." Format validation passes; semantic retention must fail.
- Nearest overlap and distinction: first-batch `compare-model-context-pairs-on-frozen-cases` designs a performance comparison, and starter `decide_what_to_leave_out_of_a_prompt` trims context. This method audits a separately generated derivative's obligations, rights, native resources, and exact model binding before any benefit study.
- Limits: obligation extraction can miss implicit meaning and a retained clause may still be misunderstood by the model. Human review and held-out task comparison remain separate gates.
