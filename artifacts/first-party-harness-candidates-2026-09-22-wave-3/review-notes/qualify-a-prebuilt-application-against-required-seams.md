# Candidate review: qualify a prebuilt application against required seams

Status: candidate only. No independent approval, native load, licence assignment, or measured benefit.

- Source and originality: Original procedure written for this batch. Need inspiration is task `15-1211.00 / 3475` in the pinned [O*NET® 31.0 Database inventory](../../occupation-grid-research-2026-09-22/README.md) by the U.S. Department of Labor, Employment and Training Administration, used under [Creative Commons Attribution 4.0](https://www.onetcenter.org/license_db.html). No task prose or third-party skill text was copied; the agency did not approve or test this candidate.
- Facets: Computer systems analyst or platform buyer; product selection project; any company with a declared interface and deployment policy. Candidate version and required environment are inputs, not invented facts.
- Typed input/output concept: `RequiredObligation[]`, `CandidatePackageVersion`, `InterfaceEvidence[]`, `DeploymentConstraint[]` to `FitGapMatrix` and `AdaptationCheck[]`.
- Effects: Read-only comparison. No installation, purchase, external query or release change is authorized.
- Good fixture: A package supports the right feature label but only schema version 1, while a mandatory field exists only in version 2. The output marks that seam unsupported and names a versioned adapter test or a blocker; it does not call the package a fit.
- Known-wrong fixtures: (1) A review counts a marketing claim of “integrates with the service” as proof that the package preserves a required refusal state. (2) A detailed vendor specification says the refusal is preserved, but no interaction under the required version and permission scope has checked it. The matrix must reject a **qualified** fit from either claim and record the second case as documented-only until independently observed.
- Search phrasings: “Can we adapt an existing app without losing required API behavior?”; “This package demos well, but will it meet our deployment and permission constraints?”
- Nearest overlap and distinction: Starter `check_for_existing_work_before_building` discovers reusable work. Wave two `qualify-a-partner-integration-proposal` examines a bilateral partnership. This method checks one prebuilt application against mandatory typed seams and adaptation losses.
- Limits: This packet cannot establish vendor truth from documentation alone or estimate total ownership cost without supplied evidence. Rights and dependencies require independent review before any customer distribution.
